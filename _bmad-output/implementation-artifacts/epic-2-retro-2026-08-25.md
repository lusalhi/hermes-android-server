## Findings

### Aggregate Views

#### 1. Architecture Delta
- **Observation:** Introduced two core packages below the UI layer:
  - [`com.hermes.node.engine`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/engine/BootstrapExtractor.kt): Houses `BootstrapExtractor`, managing streaming decompression, directory traversal guards, POSIX permission enforcement, and environment health checks.
  - [`com.hermes.node.data`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/data/ConfigRepository.kt) & [`com.hermes.node.data.model`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/data/model/HermesConfig.kt): Encapsulates `EncryptedConfigRepository` (backed by AndroidX Security Crypto / Android Keystore AES-256 GCM) and `ConfigSerializer` (atomic temp-file writer enforcing POSIX `0600` permissions on `hermes.json`).
- **Layering & Invariants:** Injected via factory into [`HermesNavGraph.kt:45-57`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/ui/navigation/HermesNavGraph.kt#L45-L57). All asynchronous I/O runs explicitly on `Dispatchers.IO`. No layering violations or cyclic dependencies were introduced.
- **Disposition:** *Accept as-is*. Architecture spine requirements (AD-2, AD-5) are faithfully fulfilled.

#### 2. Duplication & Code Symmetry Map
- **Observation:**
  - Stream decompression and disk space validation are shared across `extract` and `repair` workflows via `extractFromStream` and `cleanUserland`.
  - POSIX permission adjustments (`setReadable`, `setWritable`, `setExecutable`) are applied purposefully in `BootstrapExtractor` (directory recursion + binary executable flags) and `ConfigSerializer` (strict owner-only `0600` read/write).
- **Disposition:** *Accept as-is*. Implementations are appropriately isolated with minimal redundancy.

#### 3. God-Class & Size Growth
- **Observation:**
  - [`ServerViewModel.kt`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/viewmodel/ServerViewModel.kt) expanded to 625 lines, managing server lifecycle, telemetry polling, bootstrap orchestration, one-tap repair, settings persistence, and error handling.
  - [`DashboardScreen.kt`](file:///home/ubuntu/hermes-android-server/app/src/main/java/com/hermes/node/ui/screens/DashboardScreen.kt) grew to 788 lines with embedded card composables (`RuntimeIntegrityCard`, `ServerControlCard`, `StatusPill`).
- **Disposition:** *Defer / Process Lesson*. While manageable for Epic 2, as Epic 3 (daemon process controller, Foreground Service, WakeLock) and Epic 4 (streaming terminal console) are implemented, child process execution and UI cards should be factored into modular components (`ProcessController`, `com.hermes.node.ui.components.*`) to prevent `ServerViewModel` from becoming an overburdened coordinator.

#### 4. Pattern Divergence
- **Observation:**
  - Reactive state adheres to unidirectional data flow (UDF) through `ServerUiState` and `StateFlow`.
  - Keystore fallback mechanism handles environments where hardware Keystore provider is unavailable (e.g., specific Robolectric unit test environments) without altering production security guarantees.
- **Disposition:** *Accept as-is*.

#### 5. Spec-to-Implementation Reconciliation
- **Observation:**
  - **FR-1 (Automated Runtime Bootstrap):** `BootstrapExtractor` extracts embedded tar.xz archive, sets `0755` permissions, and writes `.bootstrap_complete` marker.
  - **FR-2 (Runtime Health & Integrity Check):** `checkHealth()` verifies existence, file type, and executable permissions for `bin/python3`, `bin/proot`, `bin/hermes`. One-tap "Repair Runtime" purges only `usr/` and reinstall cleanly without touching user database files.
  - **FR-3 & FR-5 (Keystore Credential Encryption & 0600 Config):** `EncryptedConfigRepository` uses AES-256 GCM encrypted preferences. `ConfigSerializer` atomically writes `hermes.json` with POSIX `0600` (`setReadable(true, true)`, `setWritable(true, true)`, non-executable).
  - **NFR-1 (<15s Extraction) & NFR-6 (Security at Rest):** Streaming decompression via Apache Commons Compress and AES-256 GCM encryption satisfy both performance and security targets.
- **Disposition:** *Accept as-is*. Full reconciliation with PRD and Epics specification.
